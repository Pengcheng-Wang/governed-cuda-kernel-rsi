# Preregistered experiment plan

## Measurement contract

Each benchmark records:

- UTC timestamp, hostname, GPU model, compute capability, driver, CUDA,
  PyTorch, Triton, and relevant library versions.
- Tensor shapes, dtype, causal/training mode, warm-up count, measured
  repetitions, and synchronization method.
- Median, minimum, and maximum steady-state latency across repeated timing
  groups.
- Domain metric where meaningful: effective GB/s, TFLOP/s, tokens/s, peak
  allocated memory, all-reduce algorithm bandwidth, or bus bandwidth.
- Numerical agreement against a simple reference with explicit tolerances.
- Compilation/autotuning time separately from steady-state execution.

No result is promoted when correctness fails, a backend silently falls back,
the workload changes, or the sample count is incomplete.

## Gates

1. **Static gate**: all Python files compile.
2. **One-GPU smoke gate**: small shapes pass correctness and emit valid JSON.
3. **One-GPU full microbenchmarks**: fused ops, GEMM, attention, and decode.
4. **Eight-GPU gate**: local NCCL and model scaling complete without errors.
5. **Twenty-four-GPU gate**: cross-node communication/scaling runs only after
   the eight-GPU results are internally consistent.
6. **Publication gate**: compact raw JSON, sanitized environment metadata,
   analysis, and a shared-storage README are written serially by node 0.

## Interpretation rules

- Small-shape latency and large-shape throughput are reported separately.
- Triton/CUDA teaching kernels are not assumed to beat cuBLAS or vendor
  libraries; negative results are retained.
- A100 findings are not generalized to Hopper/Blackwell features such as
  native FP8 Transformer Engine paths, TMA, WGMMA, or newer attention kernels
  without an explicit hardware caveat.
- Distributed scaling includes both achieved speedup and efficiency; aggregate
  throughput alone is insufficient.
